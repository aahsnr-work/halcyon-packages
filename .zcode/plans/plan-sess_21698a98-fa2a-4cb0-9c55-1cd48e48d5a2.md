# OBS local builds + update automation for halcyon-packages

Research base (verified, with sources in notes): OBS build VMs have **no network** (obs-docu security guide) → build-time fetchers (all rust source builds via cargo fetch, nwg-look's Go proxy, distroshelf's meson-cargo) can't build on OBS as speced; **anda-srpm-macros is Terra-only** (not in Fedora 44; cargo-rpm-macros/sccache/mold are); **`osc build` computes the buildroot server-side** (unbuilt same-project deps → `unresolvable`, no extra-repo injection); obs-build 2026 supports **`--vm-type=podman`** (unprivileged, `--net=none`) — closest local match to OBS workers; **scmsync does not watch GitHub** — pushes need a token webhook; project rebuild default is **transitive** (full dependent closure, matches our batch cascade); OBS has **no native version-bump automation** (external bot is the standard). Decisions locked in: hybrid rust handling, webhook+token trigger.

## 2. Local OBS-equivalent build harness (`tools/obs-local.sh` + `tools/obs-local/Containerfile`)
- Containerfile: fedora-minimal:44 + osc + obs-build + podman → `localhost/obs-local:44` (the ad-hoc image already built this way; now versioned in-repo).
- `tools/obs-local.sh [pkg...] [--faithful]`: privileged podman container, repo + `~/.config/osc` mounted; runs
  `osc build --local-package --alternative-project=home:halcyon041 [--vm-type=podman] Fedora_44 x86_64 anda/<pkg>/<pkg>.spec`.
  Default chroot (fast, mock-equivalent); `--faithful` uses podman vm-type with `--net=none`, reproducing OBS network isolation exactly.
- Documented limits (in notes/obs-local-builds.md): buildroot calc is server-side, so intra-project deps must already be built on OBS (bootstrap = push first, OBS orders by availability); escape hatches `-x`/`--prefer-pkgs`; host-native alternative (install obs-build, `--vm-type=podman`, no root, no nested containers).
- Keep out of `ci/` deliberately: `ci/` is in matrix.py's INFRA_PREFIXES (touch = full rebuild).
